Features

Small surface, sharp edges

Everything you need to wire an LLM to real services — and nothing you don't.

🧠

LLM-agnostic

gpt-4o-mini, Claude, Gemini, Groq, Ollama, OpenRouter — anything LiteLLM supports. Swap models with one env var.

🔁

Tool-calling loop

The model decides when to call a tool. Results are fed back into the conversation until it produces a final answer — up to a configurable iteration cap.

🛡️

Graceful degradation

Integrations without credentials are hidden from the model entirely, so it never promises something it can't actually do.

🔌

Two backends

Call provider APIs directly, or route through a local OpenConnector runtime if you've already connected the apps there.

⚡

Web UI + CLI

A zero-build single-page chat interface, plus a REPL for scripting and one-shot prompts from the terminal.

🔐

Secrets stay secret

Credentials are read from the environment only and never logged. The server binds to 127.0.0.1 by default.

Architecture

How a message flows

A thin agent loop sits between your chat and the outside world.

💬 Web UI / CLI your message
→
🔁 Agent loop LiteLLM · tool calls
→
🧰 Tool registry only what's configured
→
🌐 Services YouTube · Gmail · chat
1

You ask

The message is appended to the session history and sent to the model.

2

Model decides

It either answers directly or emits one or more tool calls with JSON arguments.

3

Tools run

Each call is dispatched to the matching integration; results go back to the model.

4

You get an answer

The loop repeats until the model replies in plain language — then history is trimmed.

Quick start

Running in under a minute

Only the LLM key is required. Every integration is optional.

terminal
cd ai-chatbot
pip install -r requirements.txt

cp .env.example .env
# edit .env: set CHATBOT_MODEL and LLM_API_KEY

python app.py        # → http://127.0.0.1:8000
python cli.py        # …or the REPL
.env
CHATBOT_MODEL=gpt-4o-mini
LLM_API_KEY=sk-…

# optional integrations
YOUTUBE_API_KEY=…
GMAIL_ACCESS_TOKEN=…
TELEGRAM_BOT_TOKEN=…
SLACK_BOT_TOKEN=…
DISCORD_BOT_TOKEN=…

# or route through a local runtime
CHATBOT_BACKEND=runtime
OPENCONNECTOR_URL=http://localhost:3000
HTTP API

Five endpoints, no surprises

The web UI is just a client of this API — build your own on top.

MethodPathBodyDescription
GET/—Chat UI
GET/api/health—Model, backend, configured tools
GET/api/tools—Tools available to the model
POST/api/chat{"message","session_id"}Send a message
POST/api/reset{"session_id"}Clear a session
curl
curl -s localhost:8000/api/chat \
  -H 'content-type: application/json' \
  -d '{"message":"Find a 10-minute Python tutorial on YouTube","session_id":"demo"}'
